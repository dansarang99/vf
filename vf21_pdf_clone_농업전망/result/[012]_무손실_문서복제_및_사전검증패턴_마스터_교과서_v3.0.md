# 제1장. 총론 및 패러다임 전환

기존의 문서 변환은 변환 후 사람이 페이지를 넘겨보며 오탈자를 찾거나 원본과 복제본을 시각적으로 1:1 대조하는 **사후 수작업 대조(Post-Conversion Brute-Force)**에 머물렀습니다. 특히 폰트(글꼴) 분야에서는 원본에 사용된 한컴 전용 폰트(`한컴바탕`, `한컴고딕`)가 워드에서 누락되어 시스템 기본 폰트로 뒤틀리는 현상을 잡지 못했습니다.

본 교과서가 정립하는 **(AX)창업기술 마스터 검증 체계**는 변환 전 원본 문서로부터 **20대 핵심 DNA**를 기계적으로 사전 추출하여 `DOCUMENT_DNA.json`으로 확정하고, 변환된 워드(DOCX) 문서를 이 명세서와 **0.1초 만에 기계적으로 맞비교하여 100% 무결성을 판정**하는 사전 예방형 품질 보증 시스템입니다.

# 제2장. 20대 코어 청사진(Blueprint) 검증 체계

## Part I. 비즈니스 및 시각 기하학 골격 (Modules 01 ~ 07)

### 01. [businessDNA.md] 조직 정체성 및 지식재산권
- **사전 추출 패턴**: 문서 성격(`[공공 학술 보고서]` vs `[기업 규격 매뉴얼]`), 원천 발행처, 저자 4인 전수 인벤토리(박한울, 김다정, 최준혁, 김지훈).
- **자동 검증 룰**: `assert len(extracted_authors) == 4`, `assert target_company_brand_applied == True`.

### 02. [DESIGN.md] 판형, 그리드 및 컨테이너 아키텍처
- **사전 추출 패턴**: 판형 실측치(`196.1mm × 266.0mm`, 556.0 × 754.0 pt Crown Quarto), Page 2 요약 라운드 사각형 카드 여부.
- **자동 검증 룰**: `w:pgSz` 0.1mm 오차 이내 일치, 컨테이너 왜곡 0건.

### 03. [STYLE.md] 시각 스타일 토큰 및 컬러 팔레트
- **사전 추출 패턴**: 표 헤더 음영(`#D5DBE0`), 요약 카드 배경(`#F5F6F8`), 브랜드 포인트(`#0099CC`, `#FF3300`), 캡션 회색(`#717171`).
- **자동 검증 룰**: 표 셀 음영(`w:shd w:fill="D5DBE0"`) 정합률 100%.

### 04. [서체, 글꼴.md] 폰트 패밀리, 임베딩 및 4중 대체 매핑 (★신규 독립)
- **왜 타이포그래피와 분리되어야 하는가?**:
  - `Typography.md`가 크기와 위계를 다룬다면, `[서체, 글꼴.md]`는 **어떤 폰트 패밀리(명조, 고딕, 영문) 파일이 실제로 연결되고, 폰트 미설치 환경에서 어떻게 대체(Fallback)되는가**를 다룹니다.
  - 한컴 전용 폰트(`한컴바탕`, `한컴고딕`, `CIDFont`)를 마이크로소프트 워드의 4대 폰트 슬롯(`ascii`, `eastAsia`, `hAnsi`, `cs`)으로 명시 매핑하지 않으면, 영문·숫자가 의도치 않게 `Cambria`나 `Calibri`로 제각각 쪼개지는 치명적 폰트 파편화가 발생합니다.
- **사전 추출 패턴**:
  - **4중 글꼴 매핑 테이블 (OOXML rFonts 매핑)**:
    - 한글(동아시아): `w:eastAsia="맑은 고딕"` (제목) / `w:eastAsia="바탕체"` (본문)
    - 영문/라틴: `w:ascii="Times New Roman"` / `w:ascii="Segoe UI"`
    - 한글 외 아시아: `w:hAnsi="Times New Roman"`
    - 복합 텍스트: `w:cs="Times New Roman"`
  - **폰트 가중치(Weight) 9단계 매핑**: 100(Thin) ~ 900(Black) 매칭.
  - **폰트 임베딩 플래그**: 타 PC 열람 시 글꼴 깨짐 방지를 위한 폰트 포함 옵션(`w:embedTrueTypeFonts`).
- **자동 검증 룰**:
  - `document.xml` 내의 모든 `w:rFonts` 태그에서 비인가 영문 폰트(`Cambria`) 출현율 0건 검증.
  - 한글 텍스트에 한글 전용 글꼴이 100% 매핑되었는지 전수 스캔.

### 05. [Typography.md] 서체 위계 계단 및 타입 스케일
- **사전 추출 패턴**: 장제목(22pt Bold) > 절(15pt Bold) > 소제목(14pt Bold) > 본문(10.5pt Regular) > 각주(7pt Regular).
- **자동 검증 룰**: 본문/제목 크기 및 굵기 오적용 0건.

### 06. [상하좌우 여백.md] 섹션 판면 규격 및 인쇄 바운딩 박스
- **사전 추출 패턴**: 상단(20mm), 하단(22mm), 좌측(22mm), 우측(22mm), 머리글(12mm), 바닥글(12mm). 1p 표지 사방 0mm.
- **자동 검증 룰**: 모든 섹션의 `w:pgMar` 값이 기준치와 100% 일치할 것.

### 07. [장평,자간,줄간격(상하).md] 미세 타이포그래피 정합 공식
- **사전 추출 패턴**: 장평 `95%` (`w:w="95"`), 자간 `-0.5pt` (`w:spacing="-10"`), 줄간격 `160%` (`w:line="384"`), 단락 전후 여백.
- **자동 검증 룰**: 37개 전 페이지의 Head(첫 20자) 및 Tail(끝 20자) 텍스트 앵커 100% 일치.

### 10. [데코레이션.md] 디자인 그래픽, 배경 아트워크, 책자 인덱스 탭

- **자동 검증 룰**: 데코레이션 에셋 복원율 100%, 배경 이미지 타일링 흰색 줄눈(Seam Gap) 0건.

### 11. [미주/각주/참조자료.md] 본문 인라인 첨자 및 각주 1:1 매핑 쌍
- **사전 추출 패턴**: 본문 내 윗첨자(`1)`, `2)`, `3)`) 위치 및 개수, 하단 각주 설명문 리스트.
- **1:1 결합 공식**: $\text{Count}(\text{본문 첨자}) \equiv \text{Count}(\text{하단 각주 설명문})$.
- **자동 검증 룰**: `pdf2docx` 겹침 오류로 인한 **Page 1 제1저자 각주 삭제 현상 원천 차단**.

# 제3장. 통합 검증 실행 알고리즘 (0.1초 Automated Linting)

20대 모듈은 변환 전 단 한 번의 실행으로 `DOCUMENT_DNA.json`으로 컴파일되며, 변환 완료 후 파이썬 기반 `dna_verifier.py`가 이를 로드하여 **0.1초 만에 전수 검증**합니다.

```python
# (AX)창업기술 20대 청사진 마스터 자동 린터 로직
def verify_document_20_dna(docx_path, dna_manifest_path):
    dna = load_json(dna_manifest_path)
    audit = {"PASS": [], "FAIL": []}
    
    # 1. 기하학 & Zero-Drift 검증 (37p == 37p)
    actual_pages = get_word_rendered_pages(docx_path)
    assert actual_pages == dna["DESIGN"]["total_pages"], "Page Drift FAIL"
    
    # 2. 20대 모듈 린팅
    check_business_dna(docx_path, dna["businessDNA"], audit)
    check_font_families(docx_path, dna["FontFamily"], audit)     # Module 04 신규
    check_typography(docx_path, dna["Typography"], audit)        # Module 05
    check_decorations(docx_path, dna["DECORATION"], audit)       # Module 10
    check_tables_checksum(docx_path, dna["TABLES"], audit)       # Module 08
    check_charts_order(docx_path, dna["CHARTS"], audit)          # Module 09
    check_footnotes_pair(docx_path, dna["FOOTNOTES"], audit)     # Module 11
    check_dynamic_page_fields(docx_path, dna["FIELDS"], audit)   # Module 15
    check_sanitized_metadata(docx_path, dna["METADATA"], audit)  # Module 18
    
    # 3. 정량적 일치율 산출
    score = len(audit["PASS"]) / (len(audit["PASS"]) + len(audit["FAIL"])) * 100.0
    return score, audit
```
